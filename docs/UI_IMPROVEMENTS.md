# UI改善点 調査レポート

調査日: 2026-07-06
対象: shikaku-master 生成サイト（トップ / 詳細1008ページ / 分野別 / 特集 / vs比較 / 自由比較）
方法: 生成HTML・CSS・JSのコードレビュー＋ローカルサーバーでの実表示確認（デスクトップ1280px / モバイル390px のスクリーンショット検証）

## 総評

機能（検索・絞り込み・並び替え・比較）とデータは揃っているが、**見た目の設計（ビジュアルヒエラルキー・情報の優先順位付け・モバイル最適化）がほぼ未着手**の状態。具体的には:

- トップページは「入力欄が6個並んでいるだけ」で、何が主役か分からない
- 一覧・詳細ページで「ユーザーが知りたい数値（受験料・合格率・難易度）」が目立たず、内部運用用語（要確認・★データ掲載）が前面に出ている
- モバイルで表・フィルタが崩れ気味／使いにくい
- 配色・余白・角丸などのデザイントークンが未定義で、ページごとに微妙にバラバラ

なお **CSSの実体は `tools/build_pages.py` 内（1491行目付近）に埋め込まれており、`site/assets/app.css` は生成物**。改善はジェネレータ側を修正して再ビルドする必要がある。

## P1: 効果が大きい改善（最優先）

### 1. トップページの情報設計（ファーストビュー）
- **検索を主役に**: 現状は検索欄とセレクト5個が同格に並ぶ。検索ボックスを大きく1本立て（ヒーロー化）し、絞り込みセレクト群は「絞り込む」として1段格下げ（折りたたみ or 補助行）にする。
- **セレクトの幅が不揃い**（モバイルで顕著）: `select` に `width:100%`（モバイル）/ グリッド配置（デスクトップ）を与え、ガタガタ感を解消する。
- **説明文が長い**: リード文2文＋「行頭のチェックを入れて…」の注意書きが常時表示。比較の説明が必要なのはUIが自明でない証拠なので、チェックボックスに「比較」ラベルを付けて注意書き自体を消す。
- **「資格を比べる（人気の比較）」52件のベタ張りリスト**がトップの大半を占め、モバイルではひたすらスクロールになる。上位8〜10件＋「すべて見る」で専用ハブページ（`/vs/index.html`）に退避する。

### 2. 検索結果リストの情報密度
- 現状1行1件で「名前＋区分バッジ＋分野/カテゴリ」のみ。**受験料・合格率・難易度**をカード右側に定位置（数値カラム）で表示し、スキャンで比較できるようにする。並び替え「受験料が安い順」を選んでも金額が見えない資格が混ざる問題も同時に解消される。
- 300件で「…他 N 件（絞り込んでください）」と切っている。**「さらに表示」ボタン**（増分レンダリング）を付ける。
- **検索が資格名の部分一致のみ**。「宅建」「FP」「簿記2級」のような略称・よみがなでヒットしない。JSONに `kana` / `aliases` フィールドを追加してマッチ対象に含めるのが、体感品質を最も上げる施策のひとつ。

### 3. 内部用語がユーザーに露出している
- 区分「**要確認**」バッジ（灰色）が1008件中297件に表示される。ユーザーには意味不明で未完成感が強い。表示上は「検定・資格」等の中立ラベルにするか、バッジ自体を非表示にして詳細ページの注記に留める。
- 分野別ページの「**★データ掲載**」はデータ運用フラグそのもの。表示するなら受験料・合格率の実数値を出し、フラグ表記はやめる。
- 詳細ページの「ハローワークコード」「情報確認日」はスペック表の中位に混在。ユーザー関心が低いので表の最下部か脚注に移す。

### 4. 詳細ページ: 重要数値のサマリ化
- 受験料・合格率・難易度・受験資格が15行のスペック表の中に埋まっている。**h1直下にKPIカード（受験料/合格率/難易度/受験資格の4枚）** を置き、表は詳細情報として下に残す構成が定石。
- 概要段落がスペック表と同内容の機械生成文の繰り返しで冗長。表があるので段落は独自解説に絞る。
- **「この資格を比較に追加」ボタンが詳細ページにない**（比較はトップに戻ってチェックが必要）。localStorage の仕組みは既にあるので追加コストは小さい。

### 5. モバイルのスペック表
- `table.spec th` が `white-space:nowrap` + `width:34%` のため、「試験科目・出題範囲」等の長い見出しがモバイルで値カラムを圧迫（実機確認済み: 値が1行3〜6文字まで潰れる）。モバイルでは `th`/`td` を縦積み（`display:block`）にするか、nowrap を解除する。
- 自由比較（compare.html）はモバイルで横スクロールになるが、**行ヘッダ（項目名）列が sticky でない**ため、スクロールすると何の行か分からなくなる。`position:sticky; left:0` を付ける。

### 6. グローバルナビゲーションの不在
- ヘッダーがロゴ＋タグラインのみ。**「分野から探す / 目的から探す / 比較 / ランキング」程度のナビ**をヘッダー（モバイルは折りたたみ）に置く。下層ページからの回遊がページ最下部の関連リンク頼みになっている。
- フッターも出典文のみ。主要ハブ（分野一覧・特集・比較）へのリンク集を置く。
- パンくずのリンク先が不統一: 詳細ページのパンくずは `index.html?major=…`、関連リンクは `bunya/*.html` と、同じ「分野」で行き先が2種類ある。`bunya/` に統一する。
- vs ページのパンくずが「トップ › 比較」で自ページ名がない。

## P2: 品質を上げる改善

### 7. 視覚デザインの土台
- **CSS変数（デザイントークン）が未定義**。色・角丸・余白がハードコードされ、ボタン/チップ/バッジのパディングや角丸が場所ごとに微妙に違う。`--color-primary` `--radius` `--space-*` 等を定義して統一する。
- **色の意味体系が衝突**: 区分バッジ（国家=赤/公的=青/民間=緑/要確認=灰）と難易度バッジ（超難関=赤〜易しい=青）が同系色を別の意味で使う。難易度は塗りバッジをやめ、アウトライン＋アイコン（★の数など）等で区分と視覚言語を分ける。
- フォントスタックが `Meiryo` 優先で Windows で古い印象になる。`"Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Noto Sans JP", Meiryo` の順を推奨。
- 全体に影・階層がなくフラットすぎる。カードに弱いシャドウ、ホバー時のリフト等を最小限追加すると「素の生成HTML」感が薄れる。
- ダークモード非対応（`prefers-color-scheme` なし）。トークン化とセットでやると安い。

### 8. アクセシビリティ
- **フィルタの `input`/`select` すべてに `<label>` がない**（placeholder と先頭 option のみ）。`aria-label` か視覚的ラベルを付ける。
- 比較チェックボックスが `title` 属性のみで支援技術に説明が伝わらない。
- `.muted`（#98a1ad on 白）はコントラスト比 約2.7:1 で **WCAG AA 不合格**。#6b7682 系も 4.9:1 でギリギリ。muted 系を1段濃くする。
- `:focus-visible` スタイル未定義（ブラウザ既定のみ）。チップ・ボタン型UIが多いので明示的なフォーカスリングを定義する。
- 検索結果件数の更新が `aria-live` でない。`#status` に `aria-live="polite"` を付けるだけで対応可能。
- 比較上限超過時に `alert()` を使用。比較バー内のインラインメッセージ（トースト）に置き換える。
- スキップリンクなし。

### 9. 状態のURL同期
- 読み込み時に `?q=` `?major=` 等を読むが、**操作後の状態はURLに書き戻されない**。絞り込み結果を共有できず、詳細ページから戻ると条件が消える。`history.replaceState` で同期する（パンくず `index.html?major=…` の動線も自然になる）。
- 比較バーのために `body{padding-bottom:64px}` が常時確保され、バー非表示でも全ページ下部に無駄な余白がある。バー表示時のみ padding を付ける。

### 10. 一覧系ページの体験統一
- 分野別（bunya）・特集（feature）ページは静的リストで、**トップにある検索・絞り込み・比較チェックが一切使えない**。少なくとも比較チェックと簡易並び替えは共通化したい（テンプレートが同じ `results` クラスを使っているので載せやすい）。
- 特集「受験者数が多い人気資格ランキング」等が100件超のベタリスト。ランキングなら順位数字・上位の強調（トップ10だけ数値カード化など）があるとページの体をなす。

## P3: 細かい表示品質

- vs リンク「危険物取扱者 と 危険物取扱者 の違い」— 甲種/乙種の区別がタイトルに反映されず、壊れたリンクに見える（データ側の表記修正）。
- 詳細ページの公式サイトが表内リンク「公式サイト」とCTAボタンの2箇所で重複。表内はドメイン名表示（例: `maff.go.jp`）にすると情報量が出る。
- 合格率など空欄項目の「公式情報で確認」が並ぶと未完成感が強い。「—（公式未公表）」等、断定的な表記に変える。
- 「同じカテゴリの資格」がJSでのベタリンク挿入。区分バッジ程度は添えたい（SEO的にも静的化が望ましい）。
- 404ページが素っ気ない。検索ボックスと主要分野チップを置くと回遊に繋がる。
- タグチップ（就職・転職 862件）のように母数の86%に付くタグは絞り込みとして機能していない。閾値を設けて表示を絞る。
- 検索入力にデバウンスなし（1008件なので実害は小さいが、`innerHTML` 全再構築のため入力中にチカつく端末がある）。
